Lawcheck checks your coding agent's edits against the architecture rules you write down.

When it checksAfter each edit, at the end of the agent's turn, and in CI.
WhereOne law reads the imports of twelve languages, from TypeScript and Python to Go and Java. Limits names the forms it misses.
PriceFree and open source under the MIT license. It runs on your machine.
AI modelOnly for rules written in prose, when you run --review, through a provider you pick and pay for, or a local Ollama.

In CI

    
The same law stops the pull request.

    

      

        
lawcheck check --base origin/main

        
It judges the files a branch changes, so people see findings only about what they change. Verdicts of the rules in prose are committed in .lawcheck/verdicts, so the job calls no model, unless you set it up to review. The whole job.

      

      

        
✕
lawcheck
lawcheck: FAIL  1 error in 2 changed files (against origin/main)
src/core/discount.ts:1  error[forbidden-use]  core may not use api (src/api/orders.ts)

      

    

  


  

    
    
One law holds

    
Uses, rules, debt and waivers.

    

      UsesImports and other uses in twelve languages. A use may_use forbids is a finding.
      Script rulesA JavaScript file that gets one file and returns findings. It can read the syntax tree.
      Rules in proseA model you pick judges them on --review. A recorded verdict saves the next call.
      DebtA check judges the change. --full lists older breaches as debt, which does not fail the run.
      WaiversOne rule off on one line, with the reason in the code. The plugin tells you when the agent adds one.
    

  


  

    
    
What I measured

    

      
I build software with coding agents, and I read their code only where a mistake costs a lot or I cannot undo it. In the code I do not read, an agent can skip a rule in CLAUDE.md. I have enforced rules of this kind on every change in real client work for many months, with Yggdrasil, an older tool of mine.

      
On 2026-11-23 I gave Claude Code the same prompt in 80 sessions of a small shop repository. In 20 of them no rule was written anywhere, and the agent made the business logic import from the HTTP handlers in

      
8 of 20
sessions, and all 10 tests passed each time.

      
In the 60 sessions with the law and the plugin, it did that in none. film/pilot.json lists every session.

      
That was one prompt, one repository and one model. I did not run sessions with the rule only in CLAUDE.md, so the pilot does not compare the two. It measured that one breach of the layers, and no other kind of rule.

Limits

    
What it does not do yet.

    
    
      
  • After three returns the plugin lets the agent finish and tells you that the check still fails.
    • 
      
  • A pull request can edit its own law. In CI, your team chooses which law judges it: the change's own, the base's or both.
    • 
      
  • Lawcheck does not read every form of use. It misses an import() of a variable, importlib.import_module, reflection, and a Java call written by its full name with no import. The forms for each language.
